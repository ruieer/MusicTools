# Передача музыки на iPod nano 2G с помощью собственного EXE

Для собственного EXE лучше не управлять iPod через USB-кабель низкоуровневым Apple-протоколом. iPod nano 2-го поколения может выглядеть как обычный съёмный диск: программа копирует на него аудиофайлы и обновляет собственную базу iTunes.

## 1. Как iPod nano 2G хранит музыку

Типичная структура тома:

```text
iPod_Control/
├── iTunes/
│   ├── iTunesDB       — основная база треков и плейлистов
│   ├── ArtworkDB      — база обложек
│   ├── iTunesPrefs    — настройки синхронизации
│   └── iTunesCDB      — кеш базы, если существует
├── Music/
│   ├── F00/
│   │   ├── ABCD.mp3
│   │   └── EFGH.m4a
│   ├── F01/
│   └── ...
└── Device/
    └── SysInfo        — сведения об iPod
```

Точки расположения могут отличаться для старых прошивок, поэтому сначала проверяйте наличие `iPod_Control/iTunes/iTunesDB`, а не название диска.

Папки `F00`–`F7F` используются как хеш-пути. Само имя трека на iPod не обязано совпадать с именем исходного файла.

Каждый файл в базе может иметь следующие данные:

- имя и исполнитель;
- альбом;
- длительность;
- номер трека и диска;
- год;
- жанр;
- номер композиции;
- относительный путь вида `:iPod_Control:Music:F00:ABCD.mp3`;
- размер и дата добавления;
- кодировку и формат;
- номер аудиодорожки;
- BPM, рейтинг и счётчик воспроизведения;
- ссылки на плейлисты;
- признак аудиокниги или подкаста.

## 2. Форматы для nano 2G

iPod nano второго поколения обычно может воспроизводить:

- MP3;
- AAC `.m4a`;
- защищённый AAC из iTunes;
- Apple Lossless `.m4a`;
- WAV;
- AIFF;
- Audible-форматы.

FLAC, WMA, Ogg и обычные `.opus` на iPod не воспроизводятся. Поэтому EXE должен:

1. Определить формат по расширению и анализу файла.
2. Для AAC/MP3 проверить совместимость параметров.
3. Для неподдерживаемых форматов конвертировать через FFmpeg в AAC или MP3.
4. При необходимости конвертировать lossless в AAC.
5. Не пытаться обходить DRM Apple или иные защиты.

Рекомендованные параметры FFmpeg:

```powershell
# AAC
ffmpeg -i input.flac -c:a aac -b:a 256k output.m4a

# MP3
ffmpeg -i input.flac -c:a libmp3lame -b:a 192k output.mp3

# Аудиокниги или речь
ffmpeg -i input.ext -c:a aac -b:a 96k output.m4a
```

Не следует повторно конвертировать уже совместимый файл. Лучше иметь каталог кеша конвертации.

## 3. Основная сложность: iTunesDB

Простое копирование MP3-файла недостаточно.

iTunesDB содержит внутренние секции:

- `mhbd` — главный заголовок базы;
- `mhlt` — список треков;
- `mhit` — одна запись трека;
- `mhla` — список альбомов;
- `mhia` — список исполнителей;
- `mhlp` — список плейлистов;
- `mhyp` — запись плейлиста;
- `mhod` — дополнительная строка имени, исполнителя, пути или другого текста;
- `mhst` — служебные секции.

Точные смещения могут отличаться по прошивке. Самостоятельная реализация опасна из-за:

- разных версий базы;
- различий схемы разных iPod;
- платформенных путей;
- контрольных сумм;
- записей с изменяющейся длиной;
- особенностей конкретных прошивок;
- мастер-плейлиста;
- записей обложек;
- неправильных ссылок треков в плейлисте.

Поэтому не стоит «угадывать» структуру iTunesDB по дампу. Надёжнее использовать уже проверенную библиотеку.

## 4. Реализация на Windows

Практичные варианты:

1. Native-компонент на C++ с libgpod.
2. Подключённый через wrapper native-код из приложения на C# или .NET.
3. Собственный reader/writer iTunesDB по открытой спецификации.
4. Отдельная консольная утилита для базы iTunesDB и GUI на WPF, WinUI или Avalonia.

Перед выбором библиотеки проверьте:

- поддержку iPod nano поколения 2;
- чтение и запись iTunesDB;
- поддержку ArtworkDB;
- лицензию для распространяемой программы;
- наличие тестов на реальном iPod с резервной копией.

Программу следует запускать только для файлов, которыми пользователь имеет право пользоваться. Не пытайтесь расшифровать FairPlay или извлекать платные DRM-файлы.

## 5. Обнаружение iPod

В Windows программа должна:

- перечислить фиксированные и съёмные тома;
- исключить сетевые и системные диски;
- искать наличие `iPod_Control/iTunes/iTunesDB`;
- искать `iPod_Control/Device/SysInfo`;
- искать `iPod_Control/Music`;
- не считать iPod найденным только по названию диска.

Полезно проверить:

- свободное место через `DriveInfo.AvailableFreeSpace`;
- размер треков после конвертации;
- размер треков на диске iPod;
- идентификатор тома;
- серийный идентификатор USB-устройства;
- сменившуюся букву диска.

Пример на C#:

```csharp
foreach (var drive in DriveInfo.GetDrives())
{
    if (!drive.IsReady)
        continue;

    if (drive.DriveType != DriveType.Removable)
        continue;

    var root = drive.RootDirectory.FullName;
    var iTunesDb = Path.Combine(root, "iPod_Control", "iTunes", "iTunesDB");

    if (File.Exists(iTunesDb))
    {
        Console.WriteLine($"Found iPod on {root}");
    }
}
```

Результат следует дополнительно проверять через структуру папок и данные `SysInfo`.

## 6. Безопасный алгоритм передачи

Рекомендуемый порядок:

1. Проверить, что iTunes и другие программы синхронизации закрыты.
2. Найти iPod и прочитать существующий iTunesDB.
3. Сделать резервную копию папки `iPod_Control/iTunes`.
4. Прочитать все существующие треки и плейлисты.
5. Сопоставить новые файлы с уже имеющимися.
6. Определить SHA-256 или метаданные для дубликатов.
7. Конвертировать несовместимые форматы во временную папку.
8. Скопировать файлы в папку `iPod_Control/Music/Fxx`.
9. Обновить iTunesDB в памяти.
10. Записать базу во временный файл рядом с оригиналом.
11. Проверить временный файл на целостность.
12. Безопасно заменить iTunesDB резервированной копией исходника.
13. Обновить ArtworkDB только после успешного обновления треков.
14. Проверить целостность базы.
15. Безопасно извлечь iPod.

Для резервных копий следует сохранить:

```text
iTunesDB.backup
ArtworkDB.backup
iTunesCDB.backup
iTunesPrefs.backup
```

Не удаляйте резервные копии сразу после записи базы.

## 7. Имена файлов и папок

Для каждого трека можно выбрать:

- группу папок `F00`–`F7F`;
- случайное имя длиной 4 символа;
- расширение совместимого формата.

Для определения папки можно использовать хеш, но лучше позволить проверенной библиотеке назначать путь сама.

В базе не следует хранить букву диска Windows вида `E:`. Путь должен быть относительным и машинно-нейтральным.

Не копируйте исходную иерархию папок пользователя на iPod без необходимости.

## 8. Метаданные

Для чтения тегов можно использовать:

- TagLib Sharp;
- ATL .NET;
- FFprobe;
- TagLib или MetaFlac;
- отдельный вызов FFmpeg.

Нормализуйте поля:

- пустой исполнитель → `Unknown Artist`;
- пустой альбом → `Unknown Album`;
- удалите управляющие символы;
- проверьте корректность Unicode;
- ограничьте длину строк согласно требованиям базы;
- переведите длительность в миллисекунды;
- нормализуйте номер трека вида `1/12`;
- храните рейтинг отдельно;
- приведите год к целому числу.

## 9. Обложки

Обложки имеют отдельную базу и являются одним из сложных элементов.

Алгоритм:

1. Извлечь встроенную обложку или внешний cover-файл.
2. Конвертировать в совместимый JPEG с помощью FFmpeg или ImageMagick.
3. Масштабировать до поддерживаемого размера.
4. Получить идентификатор обложки через library API.
5. Обновить записи в ArtworkDB.

Не копируйте обложку обычным JPEG-файлом в папку Music. Для nano 2G обложки встроены в специальный формат базы.

Примерные ограничения:

- размер: не более 600×600 пикселей;
- формат: JPEG;
- качество: около 80–90;
- одинаковую обложку можно переиспользовать для нескольких треков альбома.

## 10. Плейлисты

Поддержка в первом релизе может включать:

- мастер-плейлист всех треков;
- плейлист из папки;
- ручной плейлист с произвольным порядком.

Плейлист должен ссылаться на внутренний идентификатор трека в базе, а не на имя файла или обычный `.m3u`.

Обычный `.m3u` нельзя записать и считать iPod nano плейлистом.

## 11. Контроль и целостность базы

iTunesDB содержит служебные поля и в зависимости от прошивки хешевые данные.

Если nano не принимает базу:

- проверьте сигнатуры и длину базы;
- проверьте целостность `mhbd`;
- проверьте размеры дочерних секций;
- проверьте контрольные суммы и выравнивание;
- проверьте, не записан ли iTunesDB на неправильный смонтированный раздел;
- проверьте различия FAT32 и HFS;
- проверьте базу на реальном резервном образе iPod.

Наиболее надёжно брать существующий iTunesDB и добавлять записи в его рабочей копии через проверенную библиотеку, а не собирать базу с нуля.

## 12. Конфликт с iTunes

iTunes должен быть полностью закрыт во время записи базы.

В Windows могут работать:

- `iTunes.exe`;
- AppleMobileDeviceService;
- iPodService;
- iTunesHelper.

Не нужно принудительно завершать процессы iTunes без необходимости и без предупреждения пользователя.

Перед синхронизацией приложение может сообщать:

- iTunes найден;
- iTunes открыт;
- iPod смонтирован;
- iTunes может перезаписать базу;
- пользователь подтвердил продолжение.

## 13. Безопасное извлечение

Передача считается завершённой только после безопасного извлечения устройства.

В Windows можно:

- получить маршрут до тома;
- вызвать eject через Shell API или Device Manager;
- дождаться отключения устройства;
- не извлекать iPod принудительно после записи базы;
- не считать завершённой передачу до закрытия всех файлов базы.

## 15. Примерный цикл передачи

```csharp
var device = IpodVolumeDetector.FindNano();
var db = await IpodDatabase.OpenAsync(device.ITunesDbPath);

foreach (var source in selectedFiles)
{
    var compatibleFile = await AudioConverter.EnsureCompatibleAsync(source);
    var metadata = await MetadataReader.ReadAsync(compatibleFile);

    var relativePath = await db.AllocateMusicPathAsync(
        compatibleFile.Extension);

    var targetPath = device.Combine(relativePath);

    await CopyEngine.CopyWithRetryAsync(
        compatibleFile,
        targetPath);

    db.AddTrack(metadata, relativePath);
}

await db.WriteSafelyAsync(device.ITunesDbPath);
await ArtworkDatabase.UpdateAsync(device.ArtworkDbPath);
await device.SafeEjectAsync();
```

Сложнее всего в этой программе не копирование MP3, а корректное обновление iTunesDB и ArtworkDB.

## 16. Минимальный рабочий релиз

Первый релиз следует ограничить:

- обнаружением nano через реальный iPod;
- резервным копированием iTunesDB;
- чтением существующей базы;
- копированием MP3 и AAC;
- чтением метаданных;
- обновлением базы;
- отображением прогресса;
- корректным извлечением;
- одним мастер-плейлистом.

Второй этап:

- конвертация неподдерживаемых форматов;
- плейлисты;
- обложки;
- удаление треков;
- переименование;
- дедупликация;
- повторная синхронизация;
- откат после неудачной записи.

## 17. Тестирование

Для тестирования нужны:

- резервная копия iTunesDB;
- реальный iPod nano 2G;
- минимум два формата аудио;
- трек с кириллицей;
- трек с встроенной обложкой;
- трек с пустыми тегами;
- трек с номером диска;
- трек длительностью менее одной секунды;
- трек с несколькими плейлистами;
- проверка работы при неожиданном отключении USB;
- проверка при недостатке свободного места;
- проверка при уже открытом iTunes.

Передавать первым можно только копию треков и сначала тестировать не на единственном устройстве iPod.

## 18. Риски

Основные риски приложения:

- повреждение iTunesDB;
- потеря плейлистов;
- потеря счётчиков воспроизведения;
- потеря рейтингов;
- отсутствие совместимости с конкретной прошивкой;
- некорректные обложки;
- повреждение файлов при отключении USB;
- бесконечная перезапись базы iTunes;
- конфликт с iTunes;
- неправильное определение устройства;
- потеря DRM-файлов или конфликт с лицензиями Apple.

Надёжность достигается резервной копией, атомарной заменой базы, запретом одновременной работы iTunes и тестом на реальном устройстве.
